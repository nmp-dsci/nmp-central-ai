One URL for every project. Freeze the demos, don't host them.

Every project UI you named is the same shape: a React + Vite single-page app on a FastAPI backend. In each one's demo mode, every GET route only reads files that are already on disk. The model calls all sit behind a handful of POST routes. So the portfolio app does not need servers at all. Build each UI once under its own path, save every GET response as a file, play the recorded chats back in the browser, and serve the whole thing from one S3 bucket behind one CloudFront URL.

Why freezing works. Each backend already keeps its GET routes to committed files and puts its model calls behind one choke point. ConvFinQA has guard_llm_call() in llm.py:124-136. tau2-loop's serving/app.py:1-22 says "every GET route serves committed files". DataAgentBench's serving/app.py:1-13 says nothing reads upstream data or calls a model. Transcript RAG has a middleware in main.py:989-1028, and Data Pilot has agent_client.py:25-27. The freezer just asks those GET routes everything once, at build time.

Architecture

One front door, one bucket, one prefix per project

The visitor's request goes left to right along the top. Publishing goes bottom to top. Nothing in the top row runs code except a ten-line CloudFront Function that sends each app's deep links to that app's own index.html.

Inside one app: the fetch shim

The apps call their API with hard-coded paths: about 20 in DABstep, about 38 in DataAgentBench. Rather than edit every call site, a showcase build installs one shared shim at start-up. It intercepts calls to the app's own API and answers them from files. Normal builds never load it.

The five pieces

1 · Front door

nmp-central-ai infra/terraform/portfolio/

  • Private bucket, Origin Access Control, one distribution. This is the Data Pilot pattern in data-qa-agent/infra/terraform/demo/main.tf, reused.
  • One change from that pattern. Data Pilot sends 403/404 to /index.html, which works for one app only. With several apps, a viewer-request function routes each prefix to its own index.html.
  • State goes in the shared tfstate bucket. Publish rights are scoped by prefix on each existing *-github-deploy role.

2 · Home and bar

scripts/portfolio_render.py

  • Renders /index.html from the registry's showcase: blocks plus each project's site card.
  • /_shell/bar.js injects the portfolio bar inside a Shadow DOM.
  • The house UI is used here only. The apps are not restyled.

3 · Showcase build

in each project: make showcase

  • vite build with base=/p/<slug>/, and the router's basename set to import.meta.env.BASE_URL. That fixes the "not sub-path ready" gap for all seven apps.
  • Runs the freezer, copies the replay packs and writes showcase.json.

4 · The kit

nmp-central-ai showcase/, vendored by make install-showcase

  • freeze.py starts the app in demo mode under FastAPI's TestClient. It crawls the OpenAPI GET routes plus the id lists declared in showcase.yaml, and writes the results to _frozen/ with a coverage report.
  • shim.ts is the browser half.
  • One file-naming function is shared by both, and a parity test keeps them in step.

5 · Registry and decision

registry/projects.yaml, new decision D38

  • A showcase: block gives the slug, the site card and the phase.
  • make portfolio-status shows what is published, from which commit, and on what date.
  • A smoke test opens every app's nav routes and fails on a missing file, or on any request that leaves the URL.

The only code in the front door

// CloudFront Function, viewer-request
function handler(event) {
  var r = event.request, u = r.uri;
  var m = u.match(/^\/p\/([a-z0-9-]+)(\/.*)?$/);
  if (m && !m[2]) return { statusCode: 301,
    headers: { location: { value: u + '/' } } };
  var file = u.split('/').pop().indexOf('.') >= 0;
  if (m && !file) r.uri = '/p/' + m[1] + '/index.html';
  else if (!file) r.uri = '/index.html';
  return r;
}

Risks and failure modes

What can go wrong, and what catches it

RiskWhat the visitor would seeWhat catches or prevents it
A route the freezer missedAn empty panel or an error box in that viewA coverage report per build: OpenAPI GET routes against frozen ones. The publish smoke test opens every nav link and fails on any 404 under _frozen/.
A half-finished deployA blank page: the new index.html points at assets that are not there yetUpload hashed assets and data first and index.html last. Delete old assets one publish later.
Something private gets frozenIt is publicRun the repo's secrets scan over _frozen/ before upload. Review DataAgentBench's local-only traces by hand the first time. The other six already ship the same data in public images.
Built from the wrong commitA demo that doesn't match the case studyThe build refuses a dirty tree. showcase.json records the commit and the date, and the bar shows them. Note: tau2-loop is on opt-cycle with uncommitted changes, and DataAgentBench's newest work is on a remote branch.
Third-party requestsBreaks the "nothing leaves the URL" promiseDABstep loads Google Fonts, Transcript RAG sends PostHog analytics, and DataAgentBench iframes a local MLflow. Showcase builds self-host the fonts, drop PostHog unless you want analytics, and remove the iframe.
Recordings go staleThe demo lags behind the repoThe bar says "recorded on <date>". Re-publishing is one command, and s3 sync uploads only what changed.
App and bar styles collideBroken layout in one appThe bar lives in a Shadow DOM and takes a fixed 36 px at the top, so app CSS cannot reach it and it cannot reach the app.

Out of scope on purpose: new model calls, databases in AWS (D19), App Runner, deleting anything, and restyling any app. MLflow on AWS (M2) is unaffected.
