Why pause the App Runner services instead of deleting them

Deleting would save, at most, the $3 a month in auto-deploy fees that pausing might not stop. In exchange, it gives up the things that are hard to get back.

Pause recommended

  • Compute scales to zero. AWS: “you are only billed while your application is running.”
  • The *.awsapprunner.com domain is kept, so the 4 links on nmp-dsci.github.io keep working after a resume.
  • The stored image is kept. Resume deploys the last running version, with no build.
  • The service still exists, so the account keeps its App Runner footprint.

Cost while paused: $0 compute · unknown whether the $1/mo auto-deploy fee continues (A1–A3)

Delete

  • Every service gets a new random domain. That breaks 4 portfolio pages and DABStep-loop/README.md:75.
  • App Runner closed to new customers on 2026-04-30. AWS says existing customers can keep creating services, but it does not define what makes an account “existing”. Deleting every service could test that, and we would rather not find out.
  • Coming back means re-running each repo's Terraform and CI deploy.

Saves at most $3/mo more than pausing

What breaks while the services are paused

Deploy workflows fail slowly fix in step 1

Four repos run deploy-aws.yml after every green push to main. Each one polls for RUNNING 60 times at 20-second intervals, which takes 20 minutes, then fails. data-qa's start-deployment is rejected outright. tau2-loop's workflow is already disabled.

Demo links show an error your call, Q4

The ConvFinQA, DABStep, transcript-rag and data-pilot pages on nmp-dsci.github.io link to the demos. The CloudFront frontend stays up, but its API (data-qa-demo) won't answer.

Terraform changes are blocked known

App Runner rejects UpdateService on a paused service, so any apply that changes a service fails. Terraform does not track the pause itself, so an apply with no changes still passes.

Resume brings back the old image known

Resume deploys the version that was running before the pause, even with auto-deploy on. If main moved on, run one manual deployment after resuming. In-memory state, such as chat sessions, starts fresh.

Sleep

P=AdministratorAccess-‹acct›
for s in ap-southeast-1:convfinqa-demo ap-southeast-1:dabstep-demo \
         ap-southeast-2:yt-agent-demo  ap-southeast-2:data-qa-demo; do
  r=${s%%:*}; n=${s#*:}
  arn=$(aws apprunner list-services --profile $P --region $r \
    --query "ServiceSummaryList[?ServiceName=='$n'].ServiceArn" --output text)
  aws apprunner pause-service --profile $P --region $r \
    --service-arn "$arn" --query Service.Status --output text
done
